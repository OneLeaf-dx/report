## 1. 摘要

- **v5.7 是目前交付模型所使用的資料集**：9 類，train 7,264 / valid 401 / test 401 張影像，標註框 18,046 / 863 / 812 個。
- **與前一版 v5.6 只差一件事**：`Thrips_Damage`（薊馬葉害）的 208 張依新的標註約定重標，改為「**一張葉子一個框**」。來源框數 245 → 215，框中位面積 11.30% → 15.40%。其餘八類的影像與標註逐位元相同。
- **新約定是量出來的。** 兩位標註者各自標同樣 20 張：舊約定的中位 IoU 為 **0.746**，未達預先登記的 0.85；改為一葉一框後，同樣兩人、同樣 20 張升到 **0.899**。分歧幾乎全部來自「要分成幾個框」，不是邊界畫在哪裡。
- **評估集的量尺維持 v5.6 的水準**：九類 pooled ±2SE 全部 ≤ 0.10（最差 `Citrus_Leaf_Miner` 0.099），全類別跨 split 近重複 0 組，增強造成的框面積膨脹維持修正後的 1.000 倍。
- **另建外部影像實驗臂 `ext`**：124 張外部潛葉蛾影像只進 train，並佔用潛葉蛾既有的增強配額，兩臂的總張數完全相同，可以直接對照。

### 2.2 切分：逐類絕對評估量

v5.5 的評估集太小，例如 `Scale_Insect` 的 valid 與 test 相差 0.308，無法下任何逐類結論。v5.6 改為每類固定 valid / test 張數，張數由各類實測的 ±2SE 依 1/√n 回推，目標是 valid 與 test 合併後 ±2SE ≤ 0.10。只有四個類別的切分變動，且 v5.5 的評估影像全部保留（巢狀相容）。v5.7 完全沿用此切分。

### 2.3 增強與框膨脹修正

train 的增強配額為 `min(4 × 原始張數, 1200)`。v5.5 以前使用任意角度旋轉與鏡射邊界填充：旋轉會讓軸對齊的標註框被外接矩形撐大，鏡射則會把物件複製成多份。v5.6 起旋轉只用 90 度倍數，邊界改為複製填充。

### 2.4 標註一致性的量測方法

- 兩位標註者各自標同樣 20 張，**不互看、不預標**——預標會讓兩人向同一個起點收斂，量出來的一致性會被灌高
- 配對方式為貪婪最大 IoU；一人畫了、另一人沒畫的框以 IoU 0 計入，漏標也算不一致
- 統計量為**全部配對框的中位 IoU**，判準 ≥ 0.85，於 2026-08 登記，早於量測
- 未通過時，依量測前寫下的規則**只重測一次**：只改一條約定、同樣 20 張、判準不變
- 回收時確認標註平台匯出的影像與發派版逐位元相同，避免平台自動轉正或縮放造成座標系不一致；發派前已將帶 EXIF 旋轉標記的影像轉正

## 4. 結論與限制

1. **v5.7 是交付模型所用的資料集**，與 v5.6 只差 `Thrips_Damage` 的標註約定。
2. **`Thrips_Damage` 標註不一致的根因是「分成幾個框」的自由度**，不是邊界；拿掉這個自由度後兩人一致性由 0.746 升到 0.899。
3. **評估集的量尺維持不變**：九類 pooled ±2SE ≤ 0.10、零洩漏、零框膨脹。

限制：

- **`Thrips_Damage` 換了框定義**，以 v5.7 訓練的該類 AP 不可與 v5.6 以前的數字相比。
- **全類標註的實際一致性為 0.80 至 0.83**，低於第二輪量測的 0.899。
- **其餘八類的標註一致性從未量測**。`Scale_Insect` 是最弱的類別，應優先驗證。
- **`Thrips` 的 32 至 96 px 框帶**在 train 佔 10.4%、評估集佔 29.7%，是去洩漏規則的必然結果，現有影像池補不上。
- **潛葉蛾的 train 原始影像自 v5.5 的 161 張降到 111 張**（−31%），用來換取評估精度。
- **外部影像只有約 20 至 25 片葉**，且為離體葉白紙背景，與田間照不同域。
