> **資料來源**：Kaggle 訓練輸出的 `summary.json`、`results.csv`、`args.yaml` 與混淆矩陣（存於訓練用程式碼庫 `OneLeaf-dx/detection` 的 `Train Code/v11.5/Train_output/extracted/`，不在本文件庫版控範圍）

## 1. 摘要

- **交付權重由 v11.5（v5.6 資料集）換成 v11.5（v5.7 資料集），即對照臂 `v5.7_v11_5` 的 `last.pt`。換的理由不是模型變好，是數字終於有解釋力**：`Thrips_Damage` 在 v5.6 的框彼此矛盾（兩人一致性中位 IoU 僅 0.746），那個類別的 AP 量到的是標註噪聲；v5.7 的框依驗證過 0.899 的約定重標。
- **九類 test mAP50 0.861 不可與 v5.6 資料集上的 0.810 相比。** 新約定讓 `Thrips_Damage` 的框變大 1.36 倍，而 AP50 只要 IoU ≥ 0.5 即算命中，框愈大愈容易達標。那 +0.052 幾乎全來自這一類；**標註未變動的八類平均 AP50 為 0.8527 → 0.8508，沒有變化**。
- **`Thrips_Damage` 從 v9 延續至今的 valid / test 矛盾解除**：−0.202 → +0.121，低於顯著門檻 0.165。三輪都沒有隨評估集擴大而收斂的問題，改掉標註後一次就過。
- **外部影像對潛葉蛾無效**：外部影像臂的 `Citrus_Leaf_Miner` AP50 只比對照臂高 0.021，未達預先登記的 0.04；同一輪裡訓練資料完全沒變的 `Oily_Spot` 也移動了 +0.021。
- **九類 pooled ±2SE 全部 ≤ 0.10 的評估精度目標維持**（最差 0.099）。

### 核心評估指標總覽

| 模型 | 資料集 | 權重 | test mAP50 | test mAP50-95 | Precision | Recall | 八類平均 AP50 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| v11.5（前一個交付） | v5.6 | `last.pt` | 0.80959 | 0.60691 | 0.85839 | 0.79502 | 0.85268 |
| **v11.5 對照臂（交付）** | **v5.7** | **`last.pt`** | **0.86118** | **0.64113** | **0.90923** | **0.81247** | **0.85082** |
| v11.5 外部影像臂 | v5.7_ext | `last.pt` | 0.86499 | 0.65040 | 0.88134 | 0.83221 | 0.85884 |

八類平均 AP50 為去掉 `Thrips_Damage` 後其餘八類 pooled（valid 與 test 合併）AP50 的平均，是三者之間唯一可以直接比較的欄位。

## 2. 方法與環境

### 2.1 單一變因設計

兩個臂與 v11.5 使用**逐字相同的訓練程式**，唯一的變因是資料集：

| 對照 | 資料集的差異 | 要看的類別 |
| --- | --- | --- |
| v5.6 資料集對 v5.7 資料集（對照臂） | `Thrips_Damage` 208 張依新約定重標，其餘八類逐位元相同 | `Thrips_Damage` |
| 對照臂對外部影像臂 | train 多 124 張外部潛葉蛾影像，佔用潛葉蛾既有增強配額，總張數相同 | `Citrus_Leaf_Miner` |

資料集的組成見〈[Datasets_YOLO26_v5.7 資料集統計與標註一致性報告](../%E8%B3%87%E6%96%99%E9%9B%86%E5%88%86%E6%9E%90/yolo26_v5-7_dataset_stats.md)〉。兩本訓練 notebook 由同一份 v11.5 notebook 以程式生成；因兩臂張數完全相同、光看張數分不出來，資料集複製後會讀取 `_provenance.json` 的版本與臂別當指紋，拿錯資料集即中止。

### 2.2 超參數與環境

| 項目 | 設定 |
| --- | --- |
| 架構 | 官方 `yolo26-p2`，scale `n`，`end2end=True`、`reg_max=1`（NMS-free），無自訂模組 |
| 預訓練權重 | `yolo26n.pt` |
| 排程 | epochs 70、patience 0（關閉早停）、close_mosaic 13 |
| 最佳化 | MuSGD、lr0 0.008、lrf 0.01、momentum 0.937、cos_lr、warmup 3 輪 |
| 損失權重 | box 8.0、cls 0.8、dfl 1.5 |
| 資料 | imgsz 640、batch 20、mosaic 0.7、cache ram |
| 隨機種子 | 0 |
| 框架 | `ultralytics==8.4.121`（版本釘死） |
| 硬體與耗時 | Kaggle GPU；每輪約 160 秒，70 輪約 3.1 小時 |

### 2.3 權重與評估協定

主要結果一律報 `last.pt`：固定 70 輪的自然終點，valid 未參與任何決策，因此 valid（401 張）與 test（401 張）可以合併為 802 張的 pooled 評估。`best.pt` 由 valid 挑出、帶選擇偏誤，只作對照。mAP、Precision、Recall 來自 ultralytics `val()`（conf = 0.001）；Detection Jaccard 與 TP / FP / FN 來自混淆矩陣（conf = 0.25），兩者工作點不同，說明見〈[柑橘病蟲害辨識階段性進度週報（2026-09-07）](20260907_weekly_report.md)〉§5.4。

### 2.4 預先登記的判準

以下判準於 2026-09-13 建置資料集時寫入驗收文件，**早於兩臂訓練完成**：

| # | 問題 | 判準 |
| --- | --- | --- |
| 1 | 外部影像對潛葉蛾有沒有幫助 | 外部影像臂減對照臂的 `Citrus_Leaf_Miner` pooled AP50 **> 0.04**（逐類雜訊地板） |
| 2 | 重標有沒有解除 `Thrips_Damage` 的矛盾 | valid 與 test 的 AP50 差距絕對值 **< 0.165** |
| 3 | 其餘類別 | 不預期變化；超過 ±0.04 才需要解釋 |

逐類雜訊地板 ±0.04 是實測值：訓練資料完全未變動的類別，在不同次訓練之間就會移動這麼多。

表 3-4 中唯一加了資料的潛葉蛾，pooled 變化（+0.0209）與什麼都沒加的油斑病（+0.0211）幾乎相同，而沒動過的類別在單一 split 上甚至可以移動 ±0.05——這批外部影像沒有留下可偵測的訊號。

這是「這一批外部影像無效」，不是「外部資料普遍無效」。可能的原因有三：

1. **實際多樣性遠低於張數**：124 張有大量連拍，只來自約 20 至 25 片不同的葉子。
2. **域差距很大**：外部影像是離體葉放在白紙上拍攝，本專題是田間照；前一版模型在這批照片中只認得出 5%。
3. **配額中性的設計是替換而非加法**：外部影像佔用了潛葉蛾既有的增強配額，增強圖由 333 張降到 209 張。

## 4. 結論與限制

1. **交付 v11.5（v5.7 資料集）對照臂的 `last.pt`**（5.59 MB，位於訓練用程式碼庫的 `Train Code/v11.5/Train_output/extracted/runs/detect/v5.7_v11_5/weights/`）。
2. **外部影像臂不交付**：未通過判準，且會把 CC BY 4.0 授權的外部影像帶進交付物、衍生標註來源的義務，卻換不到可量測的效益。
3. **重標修正的是量尺，不是模型**：`Thrips_Damage` 的矛盾解除了，但標註未變動的八類沒有任何變化。在不新拍照片的前提下，模型端與資料端的工程手段均已用盡。

限制：

- **`Thrips_Damage` 的類內一致性實測為 0.80 至 0.83**，不是第二輪量測的 0.899，詳見〈[資料集分析](../README.md#資料集分析)〉。
- **`Scale_Insect` 的 valid / test 差距在同一份資料上不穩定**：v5.6 資料集、v5.7 資料集對照臂、外部影像臂依序為 0.040、0.174、0.084。它是最弱的一類，框一致性從未量測，是下一個應驗證的類別。
- **每個設定只訓練一次**，沒有重複量測；逐類雜訊地板約 ±0.04（本輪觀察到潛葉蛾 +0.044），整體 mAP50 的 run 間全距為 0.021。
- **三份 `summary.json` 的 `dataset` 欄位均記為 v5.6**，係 notebook 中寫死的字串；三次訓練的身分已由 run 名稱、`args.yaml` 與資料集指紋檢查確認，後續生成的 notebook 已改為自動取值。
